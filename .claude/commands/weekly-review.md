# /weekly-review

AOKAE経営の週次レビューを自動生成する。月曜朝に実行することを想定。

## 実行手順

1. **期間の決定**
   - デフォルト: 直近7日間（今日の0時から7日前まで、JST基準）
   - `$ARGUMENTS` に `--week YYYY-MM-DD` で開始日を指定可能

2. **データ取得**
   Supabaseから以下を期間指定で取得:
   - `revenues`: 期間の売上推移（日別 / プロダクト別）
   - `costs`: 期間のコスト
   - `leads`: 新規件数、ステータス遷移
   - `alerts`: 発生件数と既読/未読
   - `site_health`: ダウン発生回数、応答時間の悪化傾向

   GitHub APIから:
   - 期間内の workflow runs 一覧（成功/失敗、実行時間）
   - 期間内のコミット数（ブランチ別）

3. **分析視点**
   - **ハイライト**: 先週比で一番改善した指標、新たに獲得したリード上位3件
   - **課題**: 先週比で悪化した指標、未解決のアラート、失敗したワークフロー
   - **トレンド**: 4週間ぶんの推移（売上・コスト・手残り・リード）
   - **稼働**: GH Actionsの失敗率、手動介入が必要だったもの

4. **翌週のTOP3**
   以下の条件で3件を選定:
   - インパクト（売上/コスト/リスクへの影響）が大きい
   - 1週間以内に着手できる
   - 依存（他タスク待ち）がない

5. **出力フォーマット**

```
📅 AOKAE 週次レビュー (YYYY/MM/DD - YYYY/MM/DD)
━━━━━━━━━━━━━━
【✨ ハイライト】
- 売上: ¥X → ¥Y (+Z%)
- 新規リード: N件（先週+M）
- ...

【⚠️ 課題】
- ...

【📈 トレンド】
(4週推移のサマリー)

【🎯 来週のTOP3】
1. ...
2. ...
3. ...

【📝 メモ】
- 未解決の決定事項
- 次週に持ち越す項目
```

## 引数

- `--week YYYY-MM-DD`: 期間開始日を指定
- `--products salonrink,affiliate`: 対象プロダクトを絞り込み
- `--markdown`: Markdownで出力（デフォルトはプレーンテキスト）

## 注意

- 最終アウトプットはNotion/Slack/LINEいずれかに貼る想定なので、プレーンテキスト＋絵文字が基本
- 生成後に「このままLINEに送る？」「notesに保存する？」とユーザーに確認
- 感想ではなく**事実 + 数値**を優先。主観語（好調・順調等）は使わない
